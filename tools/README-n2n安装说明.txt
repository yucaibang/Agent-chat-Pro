 n2n Windows 客户端安装说明（配合 Agent Chat Pro v3.12.3+）
 面向开源发布版 · 连接参数一律以你自己的部署环境为准
════════════════════════════════════════════════════════

【本目录文件】
1. tap-windows-9.21.2.exe        → TAP 虚拟网卡驱动（OpenVPN 官方构建）
2. n2n_v3_windows_x64_v3.1.1_r1255_static_by_heiye.zip
   → n2n v3.1.1 r1255 静态编译
   → 解压后关键文件：edge.exe（客户端主程序）

【安装步骤（需管理员）】
1. 双击 tap-windows-9.21.2.exe 安装 TAP 驱动
   - 全程下一步；Win10/11 可能弹驱动签名确认，选「仍要安装」
   - 装完在「网络连接」里会多出一个 TAP-Windows Adapter 适配器（正常）
2. 解压 n2n zip，把解压出的目录放到固定位置，例如：
   C:\n2n\   （保证里面有 edge.exe）
3. 把 C:\n2n 加入系统 PATH：
   Win+R → sysdm.cpl → 高级 → 环境变量 → Path → 新建 → C:\n2n → 确定
4. 开个新 cmd 验证：
   edge --version
   → 应显示 v3.1.1… r1255 字样

【Agent Chat Pro 连接参数（以你的部署环境为准）】
超级节点地址/端口：在 ACP 设置中心 N2N 参数区填写
   （由你的 supernode 部署位置决定；本仓库不提供任何默认入口）
社区名：你的 n2n 组网社区（edge -c）
加密密钥：若你的组网启用了 edge 间加密（edge -k），在 ACP 设置页
   N2N「加密密钥」填写部署时约定的值；未启用加密则留空
SSH 目标：连上虚拟网后，目标主机在虚拟网内的地址与你的账号
   （示例形态：10.0.0.1 之类的虚拟网内地址）

【传输模式说明】
v3.12.3 已内置自动兼容：
  第 1 次连接先试 UDP（约 10 秒，若你的公网入口是 TCP 隧道会失败，正常）
  → 自动降级 TCP 模式（edge 加 -S2）→ 连接成功
  成功模式按入口缓存，第 2 次起直接 TCP。
无需手动加任何参数。
（v3.19 起可在高级设置里手动固定协议，不探测。）

【常见故障】
- 「未找到 n2n edge 命令」→ PATH 没配好，或没用新开的 cmd 验证
- edge 启动后报 TAP 错误 → TAP 驱动没装/没以管理员安装
- 网络就绪超时（两种模式都失败）→ 检查 supernode 地址端口
  是否填对；NAS/服务器端 supernode 是否在跑
  （服务器上：docker ps | grep n2n 容器应 healthy）
- 连上 N2N 但 SSH 失败 → 目标机 sshd 必须监听 0.0.0.0:22（默认就是）

【一键部署】
v3.23 起 ACP 设置页内置「N2N 体检」+「一键部署」按钮：
体检五项只读检查（平台/edge/TAP/管理员/公网入口）；
一键部署自动解压工具包到 C:\n2n、装 TAP、写 PATH、自检 edge，
无需重启应用即可连接（内置 C:\n2n 绝对路径兜底）。
